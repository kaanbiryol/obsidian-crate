# Reading extraction evaluation

Evaluated on September 22, 2026. This is a focused suitability review for Crate, not a general benchmark of the vendors.

Keep Defuddle as Crate's default extractor. Firecrawl makes sense as an optional service for fetching difficult pages, but its Markdown was not consistently cleaner in these samples. Jina is a credible alternative for browser rendering, with output and anonymous-access problems to resolve before adoption. Adding Mozilla Readability does not currently offer enough benefit to justify a second extraction engine.

| Tool | Decision for Crate | Reason |
| --- | --- | --- |
| Defuddle | Keep as the default | Already runs inside Crate's Worker and self-hosted server. The tested article output was generally focused and preserved technical content. |
| Mozilla Readability | Do not add now | Similar results for simple essays; lost the opening section and its code example on the MDN sample. It would not add JavaScript rendering. |
| Firecrawl | Consider an optional retrieval fallback | Recovered JavaScript-generated content. Its Markdown kept related links, page controls, or repository chrome in several samples, even with `onlyMainContent: true`. |
| Jina Reader | Keep as a secondary candidate | Explicit browser settings recovered the JavaScript example, but MDN code examples were absent in both tested configurations. Anonymous GitHub requests were blocked during the test. |

Crate currently makes a bounded HTML request, runs Defuddle, validates content, and invokes Defuddle's own Markdown converter. The fetch does not execute page JavaScript. Crate also intentionally removes images and media; their absence is not evidence of an extractor failure. See [the extractor](../src/cloudflare/worker/reading/extraction/document.ts), [conversion](../src/cloudflare/worker/reading/extraction/markdown.ts), and [transport](../src/cloudflare/worker/reading/extraction/transport.ts).

I fetched six public pages and compared Crate's production extraction path, upstream Defuddle cleanup defaults with asynchronous requests and replies disabled, and Mozilla Readability. Crate and Defuddle were exercised in local workerd. Readability used JSDOM, first with Crate's converter and then with ordinary Turndown plus its GFM plugin so the recommendation would not depend on compatibility with Defuddle's converter. Versions: Defuddle 0.19.4, Readability 0.6.0, JSDOM 30.1.1, Turndown 7.2.4, GFM plugin 1.0.2.

Firecrawl and Jina were called through their public APIs without API keys. Firecrawl requested Markdown with `onlyMainContent: true`. Jina used its default response. I then tested Jina's documented reader preset and explicit browser engine on the two problematic examples, and Firecrawl's raw HTML output followed by Crate's existing extractor on two pages. The services fetched their own copies; this was not a comparison against identical cached HTML for every provider. No vault data or private URLs were sent to either service.

| Sample | Observed result |
| --- | --- |
| [File over app](https://stephango.com/file-over-app) | Crate, default Defuddle, and Readability with Crate's converter produced identical article Markdown. Jina was similarly focused. Firecrawl's Markdown included related content and recommendation links. Firecrawl HTML followed by Crate's extractor matched the direct Crate output exactly. |
| [You should never be angry at work](https://www.seangoedecke.com/you-should-never-be-angry-at-work/) | All four returned substantial article text. Firecrawl also retained an unrelated article preview and site search text. |
| [Beating the Averages](https://www.paulgraham.com/avg.html) | All four returned the long essay. This sample did not establish a reason to change engines. |
| [MDN: Using the Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch) | Crate and Firecrawl retained the introduction and 23 fenced code examples. Readability omitted the opening section and retained 22 examples. Jina's default output omitted the opening section and code examples; explicitly using its browser engine and reader preset still did not recover the code examples. Firecrawl included extra page controls. |
| [Wikipedia: Progressive web app](https://en.wikipedia.org/wiki/Progressive_web_app) | Defuddle preserved a useful heading hierarchy and converted references to Markdown footnotes. The tested Readability conversions retained much more HTML or flattened headings. Firecrawl retained additional page controls and categories. |
| [Obsidian Web Clipper repository](https://github.com/obsidianmd/obsidian-clipper) | Defuddle focused on the README. Readability returned the README with some formatting problems. Firecrawl included substantial repository UI. Jina returned HTTP 403 with a temporary anonymous domain-abuse restriction, so it was not quality-scored for this page. |

A separate [JavaScript-only demonstration page](https://quotes.toscrape.com/js/) tested content retrieval, not article quality. Direct Crate extraction returned only a Login link. Firecrawl's Markdown contained all ten quotations. Jina's default response missed the quotations; its explicit browser engine, reader preset, and wait for `.quote` recovered all ten. Firecrawl's rendered HTML fed to Defuddle recovered the quotations but lost their author names and retained the login link. Rendering solves missing content, but does not guarantee correct extraction afterward.

That demonstration exposed a concrete Crate problem: the current minimum Markdown-length check accepted a login-only result because the link's URL made it long enough. Before adding a fallback, Crate should assess visible article content and reject obvious login/navigation shells. The bookmark should remain saved when article extraction is unavailable.

The deployment and cost differences matter more than replacing one Markdown formatter:

- Defuddle is an MIT-licensed library created for Obsidian Web Clipper. It includes Markdown conversion and requires no external extraction account when embedded as Crate uses it. [Defuddle](https://github.com/kepano/defuddle)
- Readability is Apache-2.0 and powers Firefox Reader View. It extracts HTML and text; page retrieval and Markdown conversion remain separate responsibilities. [Readability](https://github.com/mozilla/readability)
- Firecrawl's current Compose stack includes its API, Playwright service, Redis, RabbitMQ, and PostgreSQL. Core scraping is available locally, but its advanced managed scraping capabilities are not all included. I would not make this additional stack a requirement for self-hosting Crate. The repository is AGPL-3.0. [Self-hosting](https://docs.firecrawl.dev/contributing/self-host), [cloud comparison](https://docs.firecrawl.dev/contributing/open-source-or-cloud), [repository](https://github.com/firecrawl/firecrawl)
- Firecrawl currently advertises 1,000 free credits per month and a Hobby plan at $19/month, or $16/month billed annually, for 5,000 credits. A basic page scrape costs one credit; an HTTP error page can still consume credit. These are published prices, not a measured cost forecast for Crate. [Pricing](https://www.firecrawl.dev/pricing)
- Jina's reader service is Apache-2.0 and has a Docker option bundling a browser and document-processing dependencies. Its default stateless container needs additional operational controls for a hosted service. Optional model licenses are separate from the reader service license. Basic hosted usage is free; API-key usage is token-based. I did not verify a fixed dollar rate or run its Docker image. [Repository and Docker instructions](https://github.com/jina-ai/reader), [API pricing and model distinctions](https://jina.ai/reader/)

For Crate's Cloudflare deployment, another candidate is Cloudflare Browser Run, formerly Browser Rendering: fetch rendered HTML through `/content`, then keep Defuddle for extraction. This is an architectural recommendation based on its documented capabilities; its output was not tested in this review. The service supports waiting for rendered content and identifies its requests as bots, so it should not be presented as a way around all site restrictions. Browser time currently includes 10 minutes/day on Workers Free or 10 hours/month on Workers Paid, then $0.09 per additional browser hour on Paid; session concurrency has separate pricing. A fully self-hosted Crate deployment would need its own optional browser service to avoid depending on Cloudflare. [HTML endpoint](https://developers.cloudflare.com/browser-run/quick-actions/content-endpoint/), [pricing](https://developers.cloudflare.com/browser-run/pricing/)

The next implementation should first detect unusable extraction, then offer a bounded, opt-in browser fallback while keeping Defuddle as the normal path. Test the fallback against more real articles before choosing a default provider. Hosted providers would receive saved URLs and page content, so users should explicitly enable them. Existing clipped notes should continue to use their captured content.

This small sample does not establish global accuracy, paid-plan reliability, latency guarantees, or authenticated/paywalled coverage. Neither vendor's Docker stack was started. No app code, project dependencies, or deployments were changed. Evaluation-only dependencies, scripts, responses, and summaries are retained under `.crate/extractor-review-2026-09-22/`; only this report is added to the project documentation.
